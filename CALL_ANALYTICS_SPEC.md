# Техническое описание системы аналитики звонков для проекта Vikingi

## 📋 Обзор

Система аналитики записей телефонных разговоров менеджеров с клиентами (Отдел продаж, СТО). Смешанная схема получения аудио: **автозабор** из хранилища SpRecord3 и **ручная загрузка** отдельных файлов (инциденты, тесты, внешние записи). Транскрибация (STT) и оценка по скриптам ОП/СТО. Результаты и прослушивание — в **админке**, графики и сравнения — в **дашборде** (Metabase/Superset).

## 📥 Получение аудио: смешанная схема

### Вариант 1: Автозабор из хранилища

- **Источник:** SpRecord3 или Asterisk (сетевая папка / путь по конфигу).
- **Расписание:** ежедневно в **00:00** (или cron, например 21:00).
- **Логика:**
  - Подключение к хранилищу (UNC / SMB / локальный путь). SpRecord примонтирован в `/mnt/sprecord`.
  - Выбор файлов по маппингу: канал/внутренний номер → ОП или СТО.
  - **Копирование только на HDD server7:** `/mnt/audio_calls/calls/auto/YYYY-MM-DD/` (см. `config.AUDIO_CALLS_ROOT`).
- **Требования:** путь к хранилищу, учётные данные (если сеть), HDD примонтирован в `/mnt/audio_calls`.

### Вариант 2: Ручная загрузка

- **Интерфейс:** в админке — папки «ОП» и «СТО» (или drag & drop в раздел загрузки).
- **Назначение:** инциденты, тесты, внешние записи, разовые проверки.
- **Логика:**
  - Пользователь выбирает отдел (ОП/СТО) и загружает один или несколько WAV/MP3.
  - **Файлы сохраняются только на HDD:** `/mnt/audio_calls/calls/manual/OP/` или `/STO/`.
  - Файлы попадают в очередь обработки.
  - Опционально: ввод даты, менеджера, внутр. номера вручную.
- **Плюсы:** не нужен доступ к SpRecord, гибкость, можно запускать при отсутствии автозабора.

### Общая очередь обработки

- И автозабор, и ручная загрузка пишут в одну очередь.
- Для каждого файла задаётся `source_type`: `auto` | `manual`, `department`: `OP` | `STO`.
- Аналитика выполняется по скриптам ОП или СТО в зависимости от отдела.

## ⏰ Логика работы

### Расписание обработки

**Автозабор:** ежедневно в **00:00** (или настраиваемое время).

**Обработка (транскрибация + аналитика):** по расписанию (например, 21:00–8:00) или непрерывно (при свободном GPU).

**Приоритет (если используется общий GPU с голосовым ботом):**
1. Входящие звонки имеют приоритет.
2. Аналитика выполняется в окне без активных звонков.

**Алгоритм обработки:**
1. Сканирование очереди (файлы из автозабора + ручная загрузка).
2. **Этап 1: Транскрибация (STT).** GigaAM → сохранение транскрипций в БД.
3. **Этап 2: Аналитика по скриптам.** Оценка по критериям ОП или СТО (см. `analyze_call_quality.py`, `analyze_sto_quality.py`).
4. Сохранение результатов в БД, обновление статуса.

## 📊 Расчет объема данных

### Предположения:
- **Количество менеджеров:** 12 (внутренние номера 1-12)
- **Средняя длительность звонка:** 5 минут
- **Среднее количество звонков на менеджера в день:** 20
- **Формат записи:** WAV, 16 kHz, моно, 16-bit
- **Размер 1 минуты WAV:** ~1.9 МБ (16 kHz, 16-bit, моно)

### Расчет на 1 день:
- **Всего звонков:** 12 менеджеров × 20 звонков = 240 звонков/день
- **Общее время:** 240 звонков × 5 минут = 1200 минут = 20 часов
- **Размер аудио:** 1200 минут × 1.9 МБ = **2,280 МБ ≈ 2.3 ГБ/день**

### Расчет на 14 дней:
- **Размер аудио:** 2.3 ГБ × 14 дней = **32.2 ГБ**
- **Транскрипции (текст):** ~50 КБ на звонок × 240 звонков × 14 дней = **168 МБ**
- **Результаты аналитики (JSON/БД):** ~10 КБ на звонок × 240 звонков × 14 дней = **33.6 МБ**
- **Итого:** ~32.4 ГБ

### С запасом (20%):
- **Рекомендуемый объем диска 2:** **40 ГБ** (минимум)
- **Рекомендуемый объем с запасом:** **60-80 ГБ** (для роста и буферов)

## 💾 Требования к серверу

### Диск 1: Проект (SSD)

**Назначение:**
- Операционная система
- Код проекта Vikingi
- Модели STT/LLM/TTS
- База данных проекта
- Логи

**Характеристики:**
- **Тип:** NVMe SSD
- **Объем:** **500 ГБ - 1 ТБ**
- **Скорость чтения:** ≥ 3,500 МБ/с
- **Скорость записи:** ≥ 3,000 МБ/с
- **Интерфейс:** PCIe 4.0 x4
- **Формат:** M.2 2280

**Содержимое:**
- ОС Linux: ~20 ГБ
- Проект Vikingi: ~5 ГБ
- Модели (STT/LLM/TTS): ~15-20 ГБ
- База данных: ~10-50 ГБ (растет)
- Логи: ~5-10 ГБ
- Резерв: ~400-900 ГБ

### Диск 2: Звонки и аналитика (HDD/SSD)

**Назначение:**
- Записи звонков (14 дней)
- Результаты аналитики
- Кэш транскрипций

**Характеристики:**
- **Тип:** SATA SSD (рекомендуется) или HDD (7200 RPM)
- **Объем:** **80-120 ГБ** (минимум 60 ГБ)
- **Скорость чтения:** ≥ 500 МБ/с (SSD) или ≥ 200 МБ/с (HDD)
- **Скорость записи:** ≥ 400 МБ/с (SSD) или ≥ 180 МБ/с (HDD)
- **Интерфейс:** SATA 3.0 (6 Гбит/с)
- **Формат:** 2.5" или 3.5"

**Содержимое:**
- Записи звонков: ~32 ГБ (14 дней)
- Транскрипции: ~200 МБ
- Результаты аналитики: ~50 МБ
- Резерв: ~48-88 ГБ

**Рекомендация:** SSD предпочтительнее для быстрого доступа к файлам при прослушивании.

### Процессор и память

**Минимальные требования:**
- **CPU:** Intel Core i5-12400 / AMD Ryzen 5 5600X или выше
- **RAM:** 32 ГБ DDR4/DDR5
- **GPU:** NVIDIA RTX 3060 12GB / RTX 4060 16GB или выше (для STT + LLM)

**Рекомендуемые:**
- **CPU:** Intel Core i7-13700 / AMD Ryzen 7 7700X

### База данных

**Вариант 1: PostgreSQL (рекомендуется для интеграции с 1С)**
- Общая БД для системы аналитики и 1С
- 1С подключается через ODBC или нативный драйвер PostgreSQL
- Высокая производительность
- Поддержка транзакций

**Вариант 2: MS SQL Server**
- Если 1С работает на Windows
- Нативная поддержка в 1С
- Высокая производительность

**Вариант 3: SQLite (только для системы аналитики)**
- Если интеграция с 1С не требуется
- Простая настройка
- Не требует отдельного сервера БД

**Структура таблиц:**

**Таблица `calls`:**
- `id` - Уникальный ID (UUID или автоинкремент)
- `date` - Дата звонка (DATE)
- `time` - Время звонка (TIME)
- `internal_number` - Внутренний номер / канал (VARCHAR, напр. "E1002030-2" или 101)
- `channel_name` - Название канала из SpRecord (VARCHAR, опционально)
- `department` - Отдел: `OP` | `STO` (VARCHAR)
- `source_type` - Источник: `auto` | `manual` (VARCHAR)
- `audio_path` - Путь к аудиофайлу (VARCHAR)
- `duration` - Длительность (INTEGER, секунды)
- `transcript_path` - Путь к транскрипции (VARCHAR)
- `analytics_path` - Путь к результатам аналитики (VARCHAR)
- `status` - Статус: `pending`, `transcribed`, `analyzed`, `error` (VARCHAR)
- `manager_id` - ID менеджера в 1С (UUID, опционально)
- `customer_id` - ID клиента в 1С (UUID, опционально)
- `created_at` - Время создания записи (TIMESTAMP)

**Таблица `transcripts`:**
- `call_id` - Связь с calls (FOREIGN KEY)
- `full_text` - Полный текст транскрипции (TEXT)
- `segments` - JSON с сегментами (JSONB в PostgreSQL, TEXT в других)
- `manager_name` - Имя менеджера (VARCHAR)
- `customer_name` - Имя клиента (VARCHAR)
- `created_at` - Время создания (TIMESTAMP)

**Таблица `analytics`:**
- `call_id` - Связь с calls (FOREIGN KEY)
- `scores` - JSON с оценками по критериям (JSONB в PostgreSQL, TEXT в других)
- `total_score` - Общий балл (DECIMAL(3,2), 0-5)
- `summary` - Краткое резюме от LLM (TEXT)
- `created_at` - Время создания (TIMESTAMP)

**Индексы для производительности:**
- `calls.date`, `calls.internal_number`, `calls.department`, `calls.status`, `calls.source_type`
- `transcripts.call_id`
- `analytics.call_id`

## 🖥️ Админка (результаты + прослушивание)

**Назначение:** работа с конкретными звонками, загрузка файлов, просмотр результатов.

### Функциональность

- **Список звонков:** таблица с колонками Дата, Время, Отдел (ОП/СТО), Внутр. номер, Менеджер, Клиент, Балл, Статус, Источник (auto/manual).
- **Фильтры:** период (дата от — до), отдел, менеджер, внутренний номер, диапазон баллов.
- **Группировка по умолчанию:** по дате → по менеджеру → по внутреннему номеру.
- **Карточка звонка:**
  - Информация: дата, время, длительность, отдел, источник.
  - Аудиоплеер: прослушивание записи.
  - Транскрипция: полный текст с разделением менеджер/клиент.
  - Оценка: баллы по критериям скрипта (ОП или СТО), общий балл, резюме.
- **Загрузка файлов:** drag & drop в папку ОП или СТО; опционально указание даты и менеджера.

### Технологии

- FastAPI (или Flask) + фронтенд (React/Vue/htmx).
- HTTP-сервер для отдачи аудио (поток или скачивание).

## 📊 Дашборд (графики и сравнения)

**Назначение:** сводная аналитика, отчёты, сравнение менеджеров.

### Варианты

- **Metabase** или **Apache Superset** — подключение к PostgreSQL.
- Готовые дашборды: средний балл по менеджерам, тренды по дням/неделям, распределение оценок, топ/антитоп по критериям.

### Рекомендуемые отчёты

- Средний балл по отделам (ОП, СТО) за период.
- Сравнение менеджеров по среднему баллу.
- График числа звонков и среднего балла по дням.
- Проблемные звонки (низкий балл).
- Статистика по критериям (приветствие, имя, презентация и т.д.).

### Варианты интеграции

#### Вариант 1: Общая база данных (рекомендуется)

**Архитектура:**
- Система аналитики и 1С используют общую базу данных (PostgreSQL или MS SQL Server)
- 1С читает данные напрямую из БД через SQL-запросы

**Преимущества:**
- Единый источник данных
- Нет необходимости в промежуточных API
- Быстрый доступ к данным из 1С

- Форма звонка с детальной информацией
- Встроенный веб-браузер для прослушивания аудио (через HTTP-сервер)

**Реализация в 1С:**
- HTTPСоединение для запросов к API
- Обработка JSON-ответов
- Кэширование данных в 1С
- Формы для отображения данных

  - Оценки по критериям (0-1 или 0-5)
  - Общий балл
  - Краткое резюме от LLM

**Отчет "Статистика звонков":**
- Средний балл по менеджерам
- Графики по дням/неделям
- Топ менеджеров
- Проблемные звонки (низкий балл)

## 🔐 Безопасность

### При интеграции с 1С:

1. **Аутентификация:**
   - Используется встроенная система аутентификации 1С
   - Роли пользователей в 1С определяют доступ к данным

2. **Авторизация:**
   - Права доступа настраиваются в 1С (роли пользователей)
   - Начальник отдела: фильтр по номерам отдела
   - Директор: доступ ко всем данным
   - Проверка прав при открытии форм и запросов к БД

3. **Доступ к аудио:**
   - Если используется HTTP-сервер для аудио:
     - Токен доступа в URL (генерируется 1С)
     - Проверка прав на сервере
     - Таймаут токена (например, 1 час)
   - Если общая БД:
     - 1С проверяет права перед формированием URL
     - Аудио доступно только авторизованным пользователям

4. **Доступ к базе данных:**
   - Если общая БД:
     - Отдельный пользователь БД для 1С с ограниченными правами
     - Только SELECT для чтения данных аналитики
     - Нет прав на изменение данных аналитики
   - Если HTTP API:
     - Аутентификация через токены
     - Проверка прав на каждом запросе

5. **Логирование:**
   - Все запросы к данным аналитики логируются
   - Попытки несанкционированного доступа
   - Аудит действий пользователей в 1С

## 📞 Источники записей: Asterisk и SpRecord3

**Asterisk (IP-телефония):**
- Запись по внутренним номерам
- Формат: `номер_время.wav`
- Автозабор: планировщик копирует файлы (справочно: server7 — сохранение на HDD `/mnt/audio_calls/calls/auto/YYYY-MM-DD/`)

**SpRecord3 (аналоговая АТС Vikingi):**
- Хранилище на сервере (UNC/SMB)
- Файлы по каналам; маппинг канал → ОП/СТО задаётся в конфиге
- Автозабор: подключение по сети в 00:00, копирование по выбранным каналам
- Требуется от сисадмина: путь, учётные данные, таблица канал → отдел

**Ручная загрузка:** альтернатива при отсутствии доступа к SpRecord или для инцидентов/тестов
