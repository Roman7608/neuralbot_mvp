# 🎯 БЫСТРАЯ ДИАГНОСТИКА ГОЛОСОВОГО БОТА

## Проблема: "Звонок поступает, но бот не отвечает на речь"

### 🔧 Что исправлено:

1. **✅ MixMonitor включен** - записи звонков будут сохраняться в `/var/spool/asterisk/monitor/`
2. **✅ Кодеки настроены** - только G.711 (ulaw/alaw) в pjsip.conf
3. **✅ Обработчик голосовых звонков исправлен** - теперь реально получает аудио от Asterisk
4. **✅ Формат аудио для Salute STT** - конвертация в PCM 16-bit LE, mono, 16 kHz
5. **✅ AMI методы добавлены** - start_recording, stop_recording, playback_file
6. **✅ Дублирование эндпоинтов убрано** - исправлен конфликт в internal.py

### 🚀 Следующие шаги:

#### 1. Полный перезапуск (PowerShell):
```powershell
.\restart_bot.ps1
```

#### 2. Диагностика компонентов:
```bash
python diagnose_audio.py
```

#### 3. Проверка MicroSIP:
- Откройте настройки MicroSIP → Codecs
- Убедитесь, что **G.711 (PCMA/PCMU)** наверху списка
- **Уберите Opus** или поставьте его в конец списка
- Перезапустите MicroSIP

#### 4. Проверка сетевых настроек:
- Отключите VPN (ProtonVPN и др.)
- Временно отключите антивирус/брандмауэр
- Проверьте, что порты 8000, 5038, 5060 открыты

#### 5. Тестовый звонок:
- Звоните на extension **001**
- Говорите четко в микрофон
- Проверьте записи в `/var/spool/asterisk/monitor/`

### 🔍 Диагностика "вживую":

#### В контейнере Asterisk:
```bash
docker exec -it neuralbot_mvp_skeleton_v1.1-asterisk-1 asterisk -rvvvvv
```

#### Включить детальное логирование:
```bash
pjsip set logger on
rtp set debug on
```

### 📊 Типичные проблемы и решения:

| Проблема | Причина | Решение |
|----------|---------|---------|
| Тишина в записи | Неправильный кодек | Использовать G.711 в MicroSIP |
| STT не распознает | Неправильный формат | Конвертация в 16kHz mono |
| API недоступен | Docker сеть | Проверить host.docker.internal |
| Токены не работают | Кеш | Полный перезапуск контейнеров |

### ⚡ Если ничего не помогает:

1. **Проверьте записи звонков** - есть ли ваша речь в файлах?
2. **Используйте G.711 кодек** - никаких Opus/GSM
3. **Отключите VPN** - RTP может уходить в туннель
4. **Проверьте брандмауэр** - порты должны быть открыты
5. **Полный перезапуск** - `.\restart_bot.ps1`
