# Схема работы диалогового бота «Викинги»

Этот документ описывает логику работы стейт-машины и интентов в проекте.

## 1. Карта интентов (Intent Map)

| Интент | Ключевые слова | Обработка / Результат |
| :--- | :--- | :--- |
| **SERVICE** | записаться на сервис, на ТО, замена масла, техобслуживание, на ремонт | «Я могу записать Вас на ТО сама или перевести на ассистента сервиса» |
| **RECORD_CHOICE** | запишите, записать, да записать | Переход в сценарий записи, шаг 1: запрос ФИО и телефона |
| **HUMAN_CHOICE** | переведите, дайте человека, ассистента, менеджера, диспетчера | «Перевожу Вас на ассистента сервиса» → 103 |
| **USED_CARS** | продать, выкуп, купить мой, оценить, пробег, бу | Перевод на отдел автомобилей с пробегом (`04_transfer_used_cars.wav`) |
| **NEW_CARS_CHERY_TENET** | чери, тенет, отдел продаж, «другие марки» в контексте новых авто | Перевод на отдел продаж Чери и Тэнет (`05_transfer_chery_tenet.wav`); отдельного интента Jetour и WAV «общий ОП» нет |
| **PARTS** | запчасти, детали, расходники | Перевод на отдел запчастей |
| **ACCOUNTING** | (enum для НВ) | Только нерабочее время: фраза передачи администратору (`20_after_hours_admin.wav`), не отдельный перевод в бухгалтерию |
| **BODY_REPAIR** | кузовной, покраска, жестянка | Перевод в кузовной цех |
| **OTHER / BUY** | купить автомобиль, машина, новые | Бот сообщает список брендов и уточняет марку |

## 2. Стейт-машина (Conversation State Machine)

### Состояния:
1.  **INITIAL**: Начало диалога. Приветствие + перечисление отделов (без запроса имени).
2.  **NEED_IDENTIFIED**: Потребность понята, бот просит подтверждения (Да/Нет).
3.  **SERVICE_DATA_COLLECTION**: Сбор данных клиента (ФИО, Телефон, Марка, Дата, Работы).
4.  **SERVICE_SLOT_SELECTION**: Выбор времени из доступных в `slot.xlsx`.
5.  **SERVICE_BOOKED**: Финальное состояние — запись создана.
6.  **TRANSFERRING**: Перевод звонка на специалиста.

### Упрощение (без имени):
*   Бот **не переспрашивает** имя и **не обращается** к клиенту по имени.

## 3. Логика переходов и правила

### Начало диалога:
*   Приветствие + «Как Вас зовут?»
*   Сразу фраза перечисления отделов: «Я могу соединить Вас с Отделом продаж...»

### Правило «Двух попыток»:
*   Если бот не понимает потребность **2 раза** -> Перевод на администратора.

### Обработка «других марок» в контексте новых авто:
*   Перевод на **отдел продаж Чери и Тэнет** (`05_transfer_chery_tenet.wav`), без отдельного «общего отдела продаж» и без отдельной ветки Jetour в сценарии.

## 4. Технические детали

*   **TTS (Голос)**: Используется локальная модель Silero (голос 'xenia').
*   **Транскрипции**: Автоматическая замена латинских марок на русский (PEUGEOT -> Пеж+о) для корректной озвучки.
*   **Базы данных**:
    *   `clientsbase.xlsx`: поиск существующих клиентов.
    *   `norma.xlsx`: нормочасы для расчета длительности записи.
    *   `slot.xlsx`: график постов (запись ведется автоматически).

## 5. Алгоритм записи на сервис
1.  Извлечение работ из текста.
2.  Поиск работ в `norma.xlsx` -> Суммирование часов.
3.  Поиск свободного «окна» в `slot.xlsx` на указанную дату.
4.  Запись данных в свободный слот.
