# MAX-бот Vikingi — единый журнал настроек и действий

**Перед правками кода в `max_bot/`:** открыть и просмотреть **`docs/MAX_BOT_RECENT_CHANGES.txt`** (журнал решений и регламент) и этот файл — чтобы не повторять ошибки и не расходиться с инфраструктурой.

**Назначение:** здесь фиксируется всё, что относится к MAX в этом репозитории: как запущено, какие переменные, отличия от Telegram, планы. При смене инфраструктуры **обновлять этот файл**, чтобы не терять контекст между сессиями и людьми.

Общая справка по платформе MAX (без привязки к server7): `MAX_BOT_GUIDE.md` в корне репозитория.

## Переменные `.env` на server7

Обязательно:

```env
MAX_BOT_TOKEN=<токен из кабинета MAX, без кавычек>
```

Для кнопки «Ознакомиться с Политикой предприятия» как **ссылки в браузере** (тип `link` в API MAX):

```env
VIKINGI_PUBLIC_BASE_URL=https://ВАШ-РЕАЛЬНЫЙ-ВНЕШНИЙ-ХОСТ
```

- Значение **не выдумывается**: это тот **HTTPS-хост**, по которому из интернета уже открывается **админка** (тот же прокси, что ведёт на контейнер `admin-panel`, порт **8000** внутри Docker).
- **Без слэша в конце.** Бот сам добавит путь `/public/privacy-policy`.
- Пока сисадмин **не** опубликовал внешний HTTPS на админку — переменную **не заполнять**. Тогда кнопка политики может быть **callback**: либо краткий текст, либо **файл из контейнера** (см. ниже).

**Файл политики без публичного HTTPS:** бот читает документ с диска, загружает его в MAX (`POST /uploads?type=file`) и отправляет как вложение в чат. В `docker-compose` для `max-bot` уже смонтирован том с `.docx` в `/app/Analytic/…`; при необходимости задайте явный путь:

```env
MAX_POLICY_LOCAL_PATH=/app/Analytic/Политика обработки персональных данных Викинги (18.11.22).docx
```

Если `MAX_POLICY_LOCAL_PATH` пустой, используется этот файл **при наличии** в каталоге `Analytic/` репозитория. **Приоритет кнопки:** локальный файл → иначе ссылка `VIKINGI_PUBLIC_BASE_URL` / `MAX_POLICY_DOC_URL` → иначе краткий текст.

Альтернатива одной строкой (если URL политики другой):

```env
MAX_POLICY_DOC_URL=https://полный/путь/к/политике
```

Опционально: `MAX_API_BASE`, `MAX_POLL_TIMEOUT`, `MAX_POLL_LIMIT` — см. `max_bot/config.py`.

**Лиды в чаты MAX по отделам** (по аналогии с `GROUP_*` в `telegram_bot_config.py` для Telegram-бота). Если переменная **не задана**, в этот отдел в MAX уведомление не уйдёт (лид по-прежнему сохраняется в БД). Значение: **числовой `chat_id`** чата/канала, куда бот добавлен и может писать.

```env
MAX_CHAT_CHERY_TENET=
MAX_CHAT_JETOUR=   # опционально; если пусто, лиды с устаревшим need=jetour уходят в MAX_CHAT_CHERY_TENET
MAX_CHAT_USED_CARS=
MAX_CHAT_SERVICE=
MAX_CHAT_BODY_REPAIR=
MAX_CHAT_SPARES=
MAX_CHAT_CONSULTANT=
```

Соответствие потребностям: ОП новых авто (Chery/Tenet, единое меню), с пробегом, слесарный (ТО), кузовной, запчасти, прочие/секретарь. Реализация: `max_bot/notify_max_channels.py`.

### Где создать группы: мессенджер MAX и профиль

- **Кабинет партнёра** `business.max.ru` → **«Чат-боты»** — это настройка **бота, токена и интеграции**. Список **рабочих групп отделов** там обычно **не создаётся** (это не аналог шести Telegram-групп «из коробки»).
- **Групповые чаты под лиды** заводятся в **самом мессенджере MAX** (приложение или веб для пользователей): новая **группа**, название (например «Викинги | ОП Chery/Jetour»), участники отдела, затем в группу **добавляют бота** организации и дают право **отправлять сообщения**.
- **Под профилем «Викинги» или безразлично?**
  - **Для процессов и ответственности** лучше, чтобы группы создавали и администрировали **сотрудники от имени организации** — **корпоративный / бизнес-контекст ООО «Викинги»**, если в MAX у вас есть **профиль организации** или рабочий аккаунт, привязанный к той же организации, что и бот в `business.max.ru`. Тогда чаты явно **рабочие**, их проще передать коллегам и не путать с личными беседам.
  - **Для сервера Vikingi технически безразлично**, кто именно создал группу: интеграция использует только **`chat_id`**, который вы пропишете в `MAX_CHAT_*`. Условие одно: **бот должен быть участником этого чата** и иметь возможность **писать** туда.
  - **Не рекомендуется** вешать лиды на группу в **чисто личном** аккаунте «не из компании» или на чат, к которому потом нет доступа у дилера — риск потери канала уведомлений.
- Раздел **«Каналы»** в боковом меню кабинета чаще про **каналы вещания**, а не про закрытые операционные группы; для `MAX_CHAT_*` целевой вариант — **группа**, куда добавлен бот.
- После создания чата и добавления бота нужно получить **`chat_id`** (см. актуальную документацию MAX, логи `max-bot`, события вроде `bot_added` в `GET /updates`) и вписать в `.env`.

## Публичная политика ПДн (для ссылки из MAX)

- Эндпоинт админки: **`GET /public/privacy-policy`** — отдаёт `.docx` без входа (`admin_panel/main.py`).
- Файл на диске: `Analytic/Политика обработки персональных данных Викинги (18.11.22).docx`.
- В `docker-compose.yml` у **`admin-panel`** смонтирован тот же том, что у `telegram-bot`, иначе в контейнере файла нет → 404.
- Проверка: из интернета открыть `https://<VIKINGI_PUBLIC_BASE_URL без пути>/public/privacy-policy` — должен отдаться файл.

**В Telegram:** по кнопке политики бот шлёт **файл в чат** (`answer_document`). **В MAX** при наличии публичного URL — **открытие в браузере** по `link`; это ограничение/выбор интеграции, не «забытый» сценарий.

## Поведение в клиенте MAX (UX)

- Отдельной кнопки «Старт» как в Telegram **нет**; чат начинается при открытии бота.
- Чтобы снова показать приветствие с меню: отправить в поле сообщения **`/start`**, **`Старт`**, **`меню`** и т.п. (обработчик в `max_bot/dispatcher.py`).
- Меню — **inline-клавиатура** под сообщениями (не постоянная панель как ReplyKeyboard в TG).
- После выбора раздела показывается ответ и кнопка **«Главное меню»**, без дублирования всего списка отделов (см. `keyboards.py` / `attachments_for_menu_payload`).
- **Телефон:** кнопка **`request_contact`** («Передать номер телефона») по [доке MAX](https://dev.max.ru/docs-api) + ручной ввод `+7…`; после ввода номера — inline **«Готово»** (callback `phone_done`). Входящий контакт разбирается в `dispatcher.extract_contact_phone()` (если формат тела у платформы изменится — смотреть сырой `update` в логах).
- Запись на ТО: подтверждение слота как в TG — фразы **«да»**, **«позже»**, **«на пару часов»**, **«после обеда»**, явное время, **«другой день»** и пересчёт через `find_nearest_slot` (`lead_flow._handle_service_slot_confirm`).

## Паритет с Telegram-ботом (лиды)

- Первый шаг и уточнение отдела: часы работы, информация о дилере, **ключевые слова `NeedDetector`** и вопросы «какие отделы» (`DEPARTMENT_INQUIRY_KEYWORDS`) — см. `max_bot/lead_flow.py` и `telegram_bot/handlers/lead_handler.py`.
- Блок **«Могу ли ещё помочь?»**: часы работы, детектор потребности, доп. пожелания в тот же лид (при настроенных `MAX_CHAT_*` — в чаты MAX), новый/пробег, сервис/кузов, после двух неясных ответов — лид в «Прочие» с `source=max` в БД.
- Финализация лида: префикс **`📱 MAX`** в тексте для чатов MAX, `TelegramLeadsDB.save_lead(..., source="max")`, те же хуки ICS, что и у TG-бота — `lead_finalize.py`.

## Планы / не сделано

- Webhook на проде (HTTPS; порт **8040** для сервиса бота обсуждался с сисадмином — **пока не готово**; не подставлять чужие домены в `.env` без подтверждения).
- Таймеры неактивности как `schedule_generic_inactivity` в TG — в MAX пока нет.
- Отдельные шаги TG без полного переноса (например `WAITING_SERVICE_FINAL_CONFIRM`, фото, часть edge-case) — по запросу.
- При необходимости: `verify_license("max_bot")` после добавления модуля в JWT.

## Чеклист для сисадмина (когда будет готов внешний HTTPS)

1. Выдать стабильный **`https://домен`** на веб-админку (внутренний бэкенд: контейнер **admin-panel:8000**).
2. Убедиться, что **`/public/privacy-policy`** проксируется на тот же бэкенд.
3. Сообщить владельцу `.env` точное значение хоста → строка `VIKINGI_PUBLIC_BASE_URL=...`.
4. Отдельно согласовать **webhook MAX** (если не тот же порт/маршрут, что админка).
