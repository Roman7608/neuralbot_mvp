1. ЛИДЫ В PostgreSQL — время «по месту» (дилер)
--------------------------------------------------------------------------------
Файл: database/postgresql_manager.py

- Функция _dealer_wall_now_naive(): «стеночные» часы по POSTGRESQL_SESSION_TIMEZONE
  (или TZ, иначе Europe/Samara).
- TelegramLeadsDB.save_lead: в INSERT явно передаются created_at и updated_at (не только
  DEFAULT CURRENT_TIMESTAMP в БД), чтобы время в админке совпадало с ожидаемым местным.
- TelegramLeadsDB.update_lead_append: updated_at задаётся тем же способом.
- Уже было: при открытии соединения SET SESSION TIME ZONE (см. PostgreSQLManager).

5. ЭКРАН «ЛИДЫ» — как читать строки (пример 2026-04-06)
--------------------------------------------------------------------------------
- Источник «ТГ-бот»: запись из TelegramLeadsDB с source=telegram. Телефон в таблице —
  то, что дал клиент в Telegram; если не дал — «—». Это не голосовой Asterisk-ANI.
- Источник «голосовой бот»: source=phone; телефон — из AstDB+AMI (ORIG_ANI) и/или из
  сценария (диктовка). Если AMI не настроен (пустой ASTERISK_AMI_HOST), ANI из AstDB
  не прочитается — см. логи voice-bot.
- Источник «MAX-бот»: source=max.
- Метка времени суток «21–8» (нерабочее): в SQL это интервал 21:00–24:00 и 00:00–08:00
  по времени created_at в БД. Утренние часы 02:xx и 06:xx до 08:00 попадают в «нерабочие»
  по этому правилу — это ожидаемо, даже если «по жизни» уже утро.
