## Актуальная конфигурация Asterisk

### `asterisk/conf/pjsip.conf`

- transport:
  - `udp`
  - bind: `0.0.0.0:5060`
- registration:
  - `server_uri=sip:${INFOLADA_SIP_HOST}:${INFOLADA_SIP_PORT}`
  - `client_uri=sip:${INFOLADA_SIP_USER}@${INFOLADA_SIP_HOST}:${INFOLADA_SIP_PORT}`
  - `outbound_auth=infolada-auth`
- endpoint `infolada`:
  - `context=from-infolada`
  - `allow=alaw`
  - `allow=ulaw`
  - `direct_media=no`
  - `rtp_symmetric=yes`
  - `force_rport=yes`
  - `rewrite_contact=yes`
- identify:
  - match по IP Инфолады

### `asterisk/conf/extensions.conf`

Входящие из `from-infolada`:

1. `Answer()`
2. `Wait(0.5)`
3. формируется валидный UUID для AudioSocket
4. `AudioSocket(${call_uuid},voice-bot:9092)`
5. `Hangup()`

Поддерживаются:
- `exten => s`
- `exten => _X.`

## Актуальная конфигурация voice-bot

### В `docker-compose.yml`

- `AUDIOSOCKET_HOST=0.0.0.0`
- `AUDIOSOCKET_PORT=9092`
- `STT_SERVICE_URL=http://stt-service:8001`
- `TTS_SERVICE_URL=http://tts-service:8002`

### AudioSocket-протокол

Приведён в соответствие с Asterisk:

- `0x00` = hangup
- `0x01` = UUID
- `0x03` = DTMF
- `0x10` = audio (slin 8 kHz)
- `0xFF` = error

### Работа с входящим звуком

- VAD threshold понижен до `0.002`
- добавлено подробное логирование:
  - окончание реплики бота
  - старт ожидания речи
  - время до первого аудиофрейма
  - RMS первых чанков
  - результат STT
- добавлено защитное окно после реплики бота:
  - `POST_PLAYBACK_GUARD_MS=700`
  - первые 700 мс входящего аудио после реплики бота игнорируются как возможное эхо/мусор

1. Логи `asterisk`
2. Логи `voice-bot`
3. Есть ли:
   - `AudioSocket connection from ...`

   - `first_raw_audio_frame`
   - `first_listened_audio_frame`
   - `STT: ... -> '...'`
