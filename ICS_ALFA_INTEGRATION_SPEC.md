# Техническое задание для программиста 1С Альфа 6.0

## Интеграция с системой аналитики звонков и Telegram-ботом

**Дата:** 2026-01-31  
**Версия:** 1.0  
**База данных:** PostgreSQL 16  
**Сервер БД:** Локальный сервер 3 (IP-адрес уточнить)

---

## 📋 Обзор

Необходимо реализовать интеграцию 1С Альфа 6.0 с общей базой данных PostgreSQL и внешними системами:
1. **Системой аналитики звонков** (транскрибация, оценка качества, прослушивание)
2. **Telegram-ботом** (лиды, напоминания, оценки)
3. **Голосовым ботом** (поиск клиентов, проверка слотов, запись на сервис)

**Архитектура:**
- 1С Альфа 6.0 (Сервер 1) ↔ PostgreSQL (Сервер 3) ← Система аналитики (Сервер 3)
- Telegram-бот (Сервер 3) → 1С Альфа 6.0 (HTTP API / COM)
- Голосовой бот (Сервер 3) → 1С Альфа 6.0 (HTTP API / COM)

**Направления интеграции:**
1. **Чтение из PostgreSQL:** Аналитика звонков, лиды из Telegram
2. **Запись в 1С:** Создание событий/уведомлений при получении лидов
3. **Чтение из 1С:** Поиск клиентов, проверка слотов, данные об автомобилях
4. **Запись в 1С:** Создание записей на сервис

## 📊 2. Структура базы данных

### 2.1. Таблицы для чтения из 1С

#### Таблица `calls` (Записи звонков)
```sql
CREATE TABLE calls (
    id SERIAL PRIMARY KEY,
    file_path VARCHAR(500) NOT NULL UNIQUE,
    file_name VARCHAR(255) NOT NULL,
    internal_number INTEGER NOT NULL,  -- Внутренний номер менеджера (1-12)
    call_date DATE NOT NULL,
    call_time TIME NOT NULL,
    duration_seconds INTEGER,
    file_size_bytes BIGINT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Назначение:** Список всех записанных звонков.

#### Таблица `call_transcriptions` (Транскрипции)
```sql
CREATE TABLE call_transcriptions (
    id SERIAL PRIMARY KEY,
    call_id INTEGER NOT NULL REFERENCES calls(id) ON DELETE CASCADE,
    transcription_text TEXT NOT NULL,  -- Полный текст транскрипции
    segments JSONB,  -- Сегменты с временными метками
    diarization JSONB,  -- Результаты диаризации
    manager_segments JSONB,  -- Сегменты менеджера
    client_segments JSONB,  -- Сегменты клиента
    stt_model VARCHAR(100),
    processing_time_seconds FLOAT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(call_id)
);
```

**Назначение:** Транскрипции звонков с разделением на менеджера и клиента.

#### Таблица `call_quality_scores` (Оценки качества)
```sql
CREATE TABLE call_quality_scores (
    id SERIAL PRIMARY KEY,
    call_id INTEGER NOT NULL REFERENCES calls(id) ON DELETE CASCADE,
    transcription_id INTEGER REFERENCES call_transcriptions(id) ON DELETE SET NULL,
    
    -- Оценки по критериям (0.0 - 1.0)
    greeting_score FLOAT DEFAULT 0.0,
    professionalism_score FLOAT DEFAULT 0.0,
    clarity_score FLOAT DEFAULT 0.0,
    listening_score FLOAT DEFAULT 0.0,
    problem_solving_score FLOAT DEFAULT 0.0,
    closing_score FLOAT DEFAULT 0.0,
    overall_score FLOAT DEFAULT 0.0,
    
    detailed_evaluation JSONB,
    llm_model VARCHAR(100),
    evaluation_prompt TEXT,
    processing_time_seconds FLOAT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(call_id)
);
```

**Назначение:** Оценки качества звонков по различным критериям.

#### Таблица `call_metadata` (Метаданные)
```sql
CREATE TABLE call_metadata (
    id SERIAL PRIMARY KEY,
    call_id INTEGER NOT NULL REFERENCES calls(id) ON DELETE CASCADE,
    client_name VARCHAR(255),
    client_phone VARCHAR(50),
    car_brand VARCHAR(100),
    car_model VARCHAR(100),
    service_type VARCHAR(255),
    appointment_date DATE,
    appointment_time TIME,
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(call_id)
);
```

**Назначение:** Извлеченная информация из звонков (имена, телефоны, марки авто и т.д.).

#### Таблица `telegram_leads` (Лиды из Telegram)
```sql
CREATE TABLE telegram_leads (
    id SERIAL PRIMARY KEY,
    telegram_user_id BIGINT NOT NULL,
    telegram_username VARCHAR(255),
    client_fio VARCHAR(255) NOT NULL,
    client_phone VARCHAR(50) NOT NULL,
    need_type VARCHAR(50) NOT NULL,
    need_text TEXT,
    department VARCHAR(100) NOT NULL,
    group_id BIGINT,
    working_hours BOOLEAN DEFAULT TRUE,
    response_message TEXT,
    ics_notification_created BOOLEAN DEFAULT FALSE,
    ics_client_found BOOLEAN,
    ics_client_id VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Назначение:** Лиды от клиентов через Telegram-бот.

### 3.2. Синхронизация данных

#### Задача 1: Синхронизация звонков

**Описание:** Периодически (каждые 5-10 минут) читать новые записи из таблицы `calls` и создавать элементы справочника "Звонки".

**Алгоритм:**
1. Подключиться к PostgreSQL
2. Выполнить запрос:
   ```sql
   SELECT * FROM calls
   WHERE id > (SELECT MAX(ВнешнийID) FROM Справочник.Звонки WHERE ВнешнийID IS NOT NULL)
   ORDER BY id
   ```
3. Для каждой записи создать элемент справочника "Звонки"
4. Заполнить реквизиты из результата запроса

**Реализация:**
- Создать регламентное задание
- Или использовать обработку с кнопкой "Синхронизировать"

#### Задача 2: Синхронизация транскрипций

**Описание:** Для каждого звонка загрузить транскрипцию из таблицы `call_transcriptions`.

**Алгоритм:**
1. Для каждого звонка без транскрипции:
   ```sql
   SELECT * FROM call_transcriptions
   WHERE call_id = [ID_звонка]
   ```
2. Если транскрипция найдена, создать запись в регистре "ТранскрипцииЗвонков"

#### Задача 3: Синхронизация оценок качества

**Описание:** Загрузить оценки качества звонков.

**Алгоритм:**
1. Для каждого звонка:
   ```sql
   SELECT * FROM call_quality_scores
   WHERE call_id = [ID_звонка]
   ```
2. Создать запись в регистре "ОценкиКачестваЗвонков"

#### Задача 4: Синхронизация метаданных

**Описание:** Загрузить извлеченную информацию из звонков.

**Алгоритм:**
1. Для каждого звонка:
   ```sql
   SELECT * FROM call_metadata
   WHERE call_id = [ID_звонка]
   ```
2. Создать запись в регистре "МетаданныеЗвонков"

#### Задача 5: Синхронизация лидов из Telegram

**Описание:** Загрузить лиды из Telegram-бота.

**Алгоритм:**
1. Выполнить запрос:
   ```sql
   SELECT * FROM telegram_leads
   WHERE id > (SELECT MAX(ВнешнийID) FROM Справочник.ЛидыTelegram WHERE ВнешнийID IS NOT NULL)
   ORDER BY id
   ```
2. Для каждой записи создать элемент справочника "ЛидыTelegram"

## 🔧 4. Технические детали

### 4.1. Работа с JSONB

PostgreSQL использует тип JSONB для хранения JSON. В 1С нужно:
- Читать как строку
- Парсить JSON (если нужен доступ к полям)
- Или хранить как строку без парсинга

**Пример запроса:**
```sql
SELECT 
    id,
    transcription_text,
    segments::text as segments_text,
    diarization::text as diarization_text
FROM call_transcriptions
WHERE call_id = 1
```

### 4.2. Работа с датами и временем

PostgreSQL использует типы DATE, TIME, TIMESTAMP. В 1С:
- DATE → Дата
- TIME → Время
- TIMESTAMP → Дата и время

### 4.3. Обработка ошибок

**Важно:**
- Обрабатывать ошибки подключения к БД
- Логировать ошибки синхронизации
- Не прерывать работу 1С при ошибках

### 4.4. Производительность

**Рекомендации:**
- Использовать индексы для быстрого поиска
- Синхронизировать порциями (например, по 100 записей)
- Кэшировать часто используемые данные

## 📝 5. Примеры SQL-запросов

### Получить все звонки за период
```sql
SELECT * FROM calls
WHERE call_date BETWEEN '2026-01-01' AND '2026-01-31'
ORDER BY call_date DESC, call_time DESC
```

### Получить звонки с оценками качества
```sql
SELECT 
    c.*,
    qs.overall_score,
    qs.greeting_score,
    qs.professionalism_score
FROM calls c
LEFT JOIN call_quality_scores qs ON c.id = qs.call_id
WHERE c.call_date = CURRENT_DATE
ORDER BY qs.overall_score DESC NULLS LAST
```

### Получить транскрипцию звонка
```sql
SELECT 
    ct.transcription_text,
    ct.manager_segments::text as manager_text,
    ct.client_segments::text as client_text
FROM call_transcriptions ct
WHERE ct.call_id = 1
```

### Получить лиды из Telegram за период
```sql
SELECT * FROM telegram_leads
WHERE created_at >= '2026-01-01 00:00:00'
  AND created_at < '2026-02-01 00:00:00'
ORDER BY created_at DESC
```

## 🔍 10. Поиск клиентов в базе 1С

### 10.1. Проверка наличия клиента

**Описание:** Голосовой бот и Telegram-бот должны проверять наличие клиента в базе 1С по ФИО и телефону.

**HTTP API метод:** `GET /client/search`

**Параметры запроса:**
- `fio` (строка) - ФИО клиента
- `phone` (строка) - Телефон клиента (нормализованный, например +79001234567)

**Ответ (JSON):**
```json
{
    "found": true,
    "client_id": "uuid-клиента",
    "client_fio": "Иванов Иван Иванович",
    "client_phone": "+79001234567",
    "cars": [
        {
            "brand": "NISSAN",
            "model": "PATHFINDER",
            "year": 2020,
            "vin": "JN1TBNT30U0123456"
        }
    ]
}
```

**Алгоритм поиска:**
1. Сначала поиск по телефону (точное совпадение)
2. Если не найден - поиск по ФИО (частичное совпадение, нечувствительное к регистру)
3. Если найден - вернуть данные клиента и список автомобилей

### 10.2. Получение данных об автомобилях

**Описание:** Если клиент найден, вернуть список его автомобилей.

**Структура данных автомобиля:**
- Марка
- Модель
- Год выпуска
- VIN (если есть)
- Пробег (если есть)
- Номер (если есть)

**Реализация в 1С:**
1. Создать HTTP-метод `GET /client/search`
2. В методе:
   - Поиск клиента в справочнике "Клиенты"
   - Поиск по телефону (нормализация телефона)
   - Поиск по ФИО (гибкое сравнение)
   - Если найден - получить связанные автомобили
   - Вернуть JSON с результатами

**Пример кода 1С (упрощенный):**

## 📅 11. Проверка свободных слотов и запись на сервис

### 11.1. Проверка свободных слотов

**Описание:** Голосовой бот должен проверять наличие свободных слотов для записи на сервис.

**HTTP API метод:** `GET /appointments/slots`

**Параметры запроса:**
- `date` (строка, формат YYYY-MM-DD) - Дата записи
- `start_time` (строка, формат HH:MM) - Начальное время (опционально)
- `duration_hours` (число) - Длительность в часах (опционально, по умолчанию 1)

**Ответ (JSON):**
```json
{
    "available_slots": [
        {
            "date": "2026-02-15",
            "time": "09:00",
            "post": 1,
            "duration_hours": 1.0
        },
        {
            "date": "2026-02-15",
            "time": "10:00",
            "post": 1,
            "duration_hours": 1.0
        },
        {
            "date": "2026-02-15",
            "time": "14:00",
            "post": 2,
            "duration_hours": 1.5
        }
    ]
}
```

**Алгоритм проверки:**
1. Получить все записи на указанную дату
2. Определить рабочие часы (например, 9:00-21:00)
3. Определить доступные посты (например, 1-4)
4. Для каждого поста и каждого часа проверить занятость
5. Вернуть список свободных слотов

### 11.2. Создание записи на сервис

**Описание:** После выбора клиентом времени необходимо создать запись в 1С.

**HTTP API метод:** `POST /appointments/create`

**Параметры запроса (JSON):**
```json
{
    "client_id": "uuid-клиента",  // или null, если клиент новый
    "client_fio": "Иванов Иван Иванович",
    "client_phone": "+79001234567",
    "date": "2026-02-15",
    "time": "10:00",
    "post": 1,
    "duration_hours": 1.5,
    "car_brand": "NISSAN",
    "car_model": "PATHFINDER",
    "car_year": 2020,
    "work_list": "ТО, замена масла, замена фильтров",
    "mileage": 50000,
    "source": "voice_bot"  // или "telegram_bot"
}
```

**Ответ (JSON):**
```json
{
    "success": true,
    "appointment_id": "uuid-записи-в-1с",
    "appointment_number": "ЗВ-2026-001",
    "message": "Запись успешно создана"
}
```

**Реализация в 1С:**
1. Создать HTTP-метод `POST /appointments/create`
2. В методе:
   - Проверить, свободен ли слот
   - Если клиент не указан (client_id = null) - найти или создать клиента
   - Создать запись в справочнике "ЗаписиНаСервис" или регистре
   - Заполнить все данные
   - Вернуть ID записи

**Структура записи в 1С:**
- Клиент (ссылка на справочник "Клиенты")
- Дата записи
- Время записи
- Пост
- Длительность
- Автомобиль (марка, модель, год)
- Список работ
- Пробег
- Источник записи (голосовой бот, Telegram-бот, ручная)
- Статус (подтверждена, отменена)
