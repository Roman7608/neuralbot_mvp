Ответы от «Инфолада» по интеграции с Asterisk (запрос: SpRecord, голосовой бот, DID → направления)

================================================================================
1. SpRecord — куда и в каком виде пишет
================================================================================
   По SpRecord детали лучше уточнить у Солощева.

   Установленная модель:
   — Интерфейс: USB, управление через специальную программу под WinXP.
   — По одному и тому же интерфейсу идёт и управление, и передача голоса.
   — Формат записи: WAV/MP3 (не проприетарный).
   — Каждый вызов — отдельный файл.
   — В названии файлов номера не фигурируют: в имени только сгенерированный
     идентификатор. Номера и время звонка хранятся в закрытой БД программы
     управления. Других подробностей (путь, выгрузка на сервер Викингов,
     метаданные в файле) ответчик не знает.

   Для аналитики Викингов: без доступа к БД программы или выгрузки с DID/временем
   привязка записи к направлению по имени файла невозможна — нужно либо уточнить
   у Солощева (выгрузка, API, экспорт), либо опираться на запись из Asterisk.

================================================================================
2. Голосовой бот на сервере Викингов — SIP от Asterisk
================================================================================
   — Перенаправление вызовов по SIP на сервер Викингов возможно.

   Адреса (Infolada):
   — AMI (используется в SIP-connector 1С-Рарус «Альфа-Авто»): 217.113.112.24:5038
   — Для SIP-звонков: 217.113.112.24:5060

   Сеть/firewall:
   — Интерфейс закрыт белым списком (ACL).
   — Ответные IP-адреса сервера Викингов нужно внести в ACL у Инфолады,
     чтобы Asterisk мог инициировать SIP-сессию к голосовому боту.

   Действия Викингов: предоставить внешний (белый) IP сервера с голосовым ботом
   для добавления в ACL; при необходимости уточнить порт (5060 UDP/TCP).

================================================================================
3. Соответствие номеров (DID) направлениям
================================================================================
   Чёткой привязки DID к бизнес-единицам у ответчика нет (записано приблизительно
   со слов Солощева). Маршрутизация: звонок из сети Инфолады приходит на Asterisk
   по PJSIP; в зависимости от DID читается или не читается IVR, вызов идёт на
   Cisco MC3810 через разные PJSIP-endpoint. Для SIP-модуля «Альфа-Авто» нужны
   разные имена эндпойнтов — по ним различаются категории учёта в бизнес-аналитике.
   IVR в конфиге есть, но фиктивный: нажатие цифры считывается, на маршрутизацию
   не влияет.

   Таблица из конфигурации (DID → PJSIP-endpoint):

   DID      PJSIP-endpoint   Примечание
   ------   ---------------  ------------------------------------------
   697777   c3810_697777
   697070   c_7070           IVR
   695869   c_5869           IVR
   695870   c_5870           IVR
   695877   c_3810           отключен
   707799   c3810_707799     IVR
   772200   8482772200       номер через регистрацию (куда зарегистрирован —
                             туда и идёт вызов)

   Для аналитики Викингов: при записи звонков в Asterisk (или при передаче
   вызова на бота) передавать DID или имя эндпойнта (c3810_697777, c_7070, …)
   и на стороне Викингов хранить маппинг DID/эндпойнт → направление (ОП новых,
   ОП с пробегом, слесарный, кузовной, запчасти, хостес). Окончательную таблицу
   DID → бизнес-направление желательно согласовать с Солощевым/Инфоладой.

Краткие выводы для проекта Викинги
================================================================================
   • SpRecord: детали и возможность выгрузки/метаданных — у Солощева; по
     текущему ответу привязка записи к номеру/времени по имени файла недоступна.
   • Голосовой бот: SIP на 217.113.112.24:5060; нужно внести IP сервера Викингов

   • DID: таблица эндпойнтов выше; маппинг DID/эндпойнт → отдел уточнить и
     заложить в конфиг аналитики/бота.
