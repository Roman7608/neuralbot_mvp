================================================================================
ЗАДАЧИ ДЛЯ ПРОГРАММИСТА 1С (ИНТЕГРАЦИЯ С ПРОЕКТОМ ВИКИНГИ)
Конфигурация: 1С Альфа 6.0
================================================================================

--- ОБЩИЕ УСЛОВИЯ ---
• Стыковка: REST API 1С (HTTP-сервисы). Исходим из того, что готовых методов под запись на ТО и лиды в 1С пока нет — их нужно спроектировать и реализовать.
• Инициатор запросов: наш сервер (голосовой бот, телеграм-бот, бэкенд аналитики). 1С запросы к нам пока не инициирует.
• Тестовая база: отдельная не требуется.
• Авторизация: рекомендуется схема «логин + пароль приложения» или «токен (API Key) в заголовке» для доступа к HTTP-сервисам 1С; HTTPS при обращении извне. Конкретный механизм согласовать с руководителем IT.

================================================================================
ЭТАП 1. ЛИДЫ И СОБЫТИЯ В 1С (ПРИОРИТЕТ 1)
================================================================================

1.1. Спроектировать и реализовать HTTP-сервис 1С для приёма лидов/событий.
     Входные данные (пример): идентификатор лида, ФИО, телефон(ы), email, суть запроса (направление: ОП новых / ОП с пробегом / слесарный цех / кузовной цех / запчасти / прочие), дата/время события, источник (телеграм-бот / голосовой бот), при необходимости — марка/модель авто, комментарий.
     Действие в 1С: создание события или заявки и назначение ответственного сотрудника (по направлению).

1.2. Описать контракт API для приёма лидов: метод (POST), URL, формат тела запроса (JSON), обязательные и опциональные поля, коды ответов (200, 400, 500).

1.3. Реализовать авторизацию вызовов к этому HTTP-сервису (см. общие условия выше).

1.4. Передать нашей стороне: описание API (URL, пример запроса, требования к заголовкам) для подключения ботов.

================================================================================
ЭТАП 2. ЗАПИСЬ НА ТО (СЛЕСАРНЫЙ ЦЕХ) (ПРИОРИТЕТ 2)
================================================================================

2.1. Получение свободных слотов (для голосового и телеграм-бота).
     • HTTP-сервис 1С: метод получения свободного времени по «карточке записи в слесарный цех» с учётом поста (поста/постов).
     • Вход: дата (или диапазон дат), идентификатор поста (при необходимости), длительность слота (минуты).
     • Выход: список свободных слотов (дата, время начала, время окончания, пост — при необходимости).
     • Логика в 1С: учёт уже занятых слотов в карточке записи; при необходимости — учёт «нужного времени» из Excel-файлов по автомобилю и видам работ (см. п. 2.4).

2.2. Создание записи на ТО (занятие слота).
     • HTTP-сервис 1С: метод создания записи в карточке записи в слесарный цех.
     • Входные поля:
       — ФИО
       — Телефон (основной и дополнительный — 2 ячейки)
       — E-mail
       — Марка и модель автомобиля
       — Год выпуска
       — Пробег
       — Двигатель: объём, тип топлива, буквенный код
       — Трансмиссия: тип и код коробки, буквенный код, полный или передний привод
       — Желаемые дата и время (слот)
       — Вид работ
       — Комментарий
     • Действие в 1С: создание записи, занятие слота на посту в карточке записи.

2.3. Ответ 1С при создании записи (для сохранения в PostgreSQL нашей стороной):
     • ID созданной записи в 1С
     • Подтверждённое дата и время
     • Статус: принята / отменена (или аналог)

2.4. Учёт «нужного времени» из Excel для автомобиля и работ.
     • Уточнить источник данных в 1С: это справочники/документы, связанные с маркой/моделью и видами работ, или загрузка из Excel.
     • Обеспечить, чтобы при запросе свободных слотов (п. 2.1) и при создании записи (п. 2.2) использовалось правильное «трудозатратное» время по авто и работам (из Excel или аналога в 1С).

2.5. Отмена записи (освобождение слота).
     • HTTP-сервис 1С: метод отмены записи по ID (например, ID из п. 2.3).
     • Ответ: успех/ошибка. Наша сторона по этому же ID обновит статус в PostgreSQL.

2.6. Передать нашей стороне: описание всех методов (получение слотов, создание записи, отмена), форматы запросов/ответов, примеры — для интеграции голосового и телеграм-бота.

Подробные рекомендации по реализации (публикация HTTP-сервисов, методы, форматы JSON, примеры запросов/ответов, пошаговый план в 1С) — см. раздел «РЕКОМЕНДАЦИИ ПО РЕАЛИЗАЦИИ (ЭТАП 2)» в файле Tasks_1C_integration_1.txt.

================================================================================
ЭТАП 3. АНАЛИТИКА ТЕЛЕФОННЫХ ПЕРЕГОВОРОВ И ДОСТУП ИЗ 1С (ПРИОРИТЕТ 3)
================================================================================

3.1. Доступ из 1С к результатам аналитики звонков.
     • Два алгоритма/набора отчётов: по Отделу продаж и по Ассистентам сервиса (отдельно).
     • Что должно быть доступно из 1С (уточнить с заказчиком): список звонков с датой, длительностью, направлением, оценкой/результатом аналитики, ссылкой на аудиофайл (или способом воспроизведения).

3.2. Спроектировать способ доступа к аудиофайлам из 1С.
     Варианты (на выбор 1С и IT):
     — HTTP-ссылки на аудиофайлы (наш сервер отдаёт файл по токену/времени жизни);
     — отдельный REST-метод на нашей стороне «получить аудио по ID звонка», 1С вызывает его и отдаёт пользователю ссылку или поток.
     Требования: безопасность (доступ только авторизованным пользователям 1С), возможность прослушивания из интерфейса 1С или по ссылке.

3.3. Реализовать в 1С: интерфейс (форма/отчёт) для просмотра списка звонков по выбранному алгоритму (продажи / сервис) и воспроизведения аудио (по ссылке или через встроенный плеер).

3.4. Согласовать с нашей стороной формат выдачи данных аналитики (REST API или выгрузка): перечень полей (ID звонка, дата, направление, оценка, ссылка на аудио и т.д.) и способ доставки в 1С.
