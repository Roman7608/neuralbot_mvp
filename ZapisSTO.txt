ПОЛНЫЙ СЦЕНАРИЙ ГОЛОСОВОЙ ЗАПИСИ НА ТО v2 (2026-06-13) — ЭТАЛОН ДЛЯ КОДА
================================================================================

Назначение: согласованный с заказчиком сценарий упрощённой записи на ТО в
голосовом боте (v2, триггер `australia`). Реализация: `dialog/bot_logic.py`,
`dialog/sto_to_summary_table.py`, WAV/TTS, лиды/админка.

**Старый блок «ПОЛНЫЙ СЦЕНАРИЙ … 2026-05-29» ниже в файле — архив; при расхождении
приоритет у v2.**

--- Общие правила ---

  • Вход в **ветку записи** — только триггер **«австралия»** в реплике клиента
    (`TO_BOOKING_TEST_TRIGGERS` в bot_logic.py).
  • «Сервис» / «запись на ТО» **без** «австралии» → сразу ассистент сервиса
    **697777**, без записи (прод-ограничение до снятия триггера).
  • **Диспетчер** = **ассистент сервиса** = **ассистент** = **человек** =
    **менеджер** — в **ветке записи на ТО** всегда перевод на **697777** (не ОП,
    не администратор). В INITIAL (выбор отдела без записи) глобальные правила
    могут отличаться.
  • Успешный финал — **реальная запись в 1С** (`GET /service/appointments`), затем
    прощание.
  • **Лид / журнал / админка:** всё собранное из речи + **Caller ID** + дата/время
    звонка (в т.ч. при прерывании).
  • **duration_min** для одного регламентного ТО в 1С: **150** (2,5 ч), если иное
    не следует из `operation_unknown` (120 мин).

--- A. Вход: «Австралия» ---

**A.1 Рабочее время**

  1. Бот: «Поняла.»
  2. WAV **`14_service_choice.wav`** — текст **фиксированный** (не вариант RAG
     «Что Вас интересует…»):
     «Я могу записать Вас на техн+ическое обсл+уживание сама или могу перевести
     вас на ассистента сервиса.»
  3. Ожидание второго ответа (NEED_IDENTIFIED).

**A.2 После меню 14 — пять исходов**

  | ID  | Реплика клиента | Действие |
  |-----|-----------------|----------|
  | 2.1 | «запишите», «записаться», «дальше», «продолжай», «сделай сама», «давай», снова «Австралия» | → **сбор данных, шаг B.1** |
  | 2.2 | Маркеры перевода на ассистента (см. «Маркеры 697777») | → «Перевожу на ассистента сервиса» → **697777** |
  | 2.3 | Неясно (**1-й раз**): тишина, «алло», «что?», «не понял», «хочу на сервис» без выбора | → **повтор меню 14** (тот же WAV/текст) |
  | 2.4 | Неясно (**2-й раз** подряд) | → **697777** |
  | 2.5 | Вопрос **о стоимости** ТО: «сколько стоит», «цена», «стоимость» + то / техобслуживание / техническое обслуживание | → **697777** (без сбора, **без** Excel) |

**A.3 Нерабочее время (v2)**

  «Австралия» → «Поняла…» → запрос **имени** → подтверждение контакта → лид
  «нерабочее время» → **конец** (полной записи и 1С нет).

--- Маркеры перевода на ассистента сервиса (697777) в ветке записи ---

  Эквивалентны друг другу: **диспетчер**, **ассистент сервиса**, **ассистент**,
  **человек**, **менеджер** (+ «переведите», «переводите», «оператор», «живой»
  где применимо).

  **Не путать:** «**Дальше**», «**продолжаем**», «**запиши**», «**записывай**» —
  это **продолжение записи**, не перевод.

--- B. Линейный сбор (шаги 1–6) ---

Принцип шагов **1–2 и 6:** вопрос → окно **8 с** → **всегда** следующий шаг;
сохраняется то, что распознали (может быть пусто). Шаги **3–4:** при пустом STT
(тишина / не распознано) — **повтор вопроса** (до **2** попыток), затем переход
дальше с пустым полем. Без «верно/неверно» на каждом поле. Поиск в 1С по карточке
клиента на этом этапе **не** обязателен (упрощение v2); данные — из речи.

**Окно записи (v2, SERVICE_DATA_COLLECTION):** не менее **8 с**; VAD мягче
(`silence_ms` **800**); после начала речи — продление сбора до **12 с**;
короткий всплеск эха **< 1,2 с** в пределах окна не считается ответом.
Переменные: `VOICE_SERVICE_DATA_COLLECTION_WAIT_SEC`, `VOICE_V2_SERVICE_DATA_SILENCE_MS`,
`VOICE_V2_SERVICE_DATA_DISCARD_MAX_SEC`. Код: `services/voice/session.py`.

**B.1 Шаг 1 — имя и фамилия**

  «Пожалуйста, сейчас только отвечайте на мои вопросы. Назовите Ваши **имя и
  фамилию**.»
  8 с → шаг 2. Поля: имя, фамилия (**без отчества**).

**B.2 Шаг 2 — телефон для звонка**

  «Назовите номер телефона, на который Вам удобно **принять звонок**.»
  8 с → шаг 3. Caller ID — отдельно в лид.

**B.3 Шаг 3 — марка и модель**

  «Назовите **марку и модель** автомобиля.»
  8 с → шаг 4.

**B.4 Шаг 4 — год и пробег**

  «Назовите **год выпуска** автомобиля и **пробег в километрах**.»
  8 с → шаг 5.

**B.5 Шаг 5 — ворота (первый заход, без цены)**

  **Первый заход на шаг 5** (клиент **ещё не** спрашивал стоимость ТО) — **без
  изменений**: после шага 4 бот **один раз** озвучивает полный текст ворот ниже.
  Повторять этот длинный текст **не** нужно — только после блока **D** (см. **B.5a**).

  «В автоматическом режиме я могу записать только на **техническое обслуживание**
  и простые слесарные работы вроде **замены тормозных колодок**. Если Вам нужна
  **консультация**, скажите **«Диспетчер»** — переключу **без продолжения записи**.
  Если хотите **продолжить запись**, скажите **«Дальше»**.»

  | ID  | Ответ | Итог |
  |-----|-------|------|
  | 5.1 | Маркеры **697777** | Прерывание записи → **697777** |
  | 5.2 | «дальше», «далее», «продолжай», «запиши», «записывай», «продолжаем» | → **шаг 6** |
  | 5.3 | «Сколько стоит ТО?» (+ маркеры цены и ТО) | → **блок D** → после D см. **B.5a** |
  | 5.4 | Прочее (не 5.1–5.3) | «Поняла, **прерываю запись** и перевожу Вас на ассистента сервиса.» → **697777** |

**B.5a После блока D (возврат в сценарий; не второй заход B.5)**

  Когда клиент **уже** спросил цену и отработал блок **D** — **не** повторять
  длинные ворота B.5. Короткий вопрос:

  «**Продолжаем запись** или **перевожу Вас на ассистента сервиса**?»

  | Ответ | Итог |
  |-------|------|
  | «продолжаем», «дальше», «запиши», «записывай» (+ «продолжай», «давайте») | → следующий шаг сценария (с шага 5 — **шаг 6**) |
  | «переведи», «человек», «ассистент», «диспетчер», «менеджер» | → **697777** |
  | Неясно (1-й раз) | Повтор: «Продолжаем запись или перевожу Вас на ассистента сервиса?» |
  | Неясно (2-й раз) | → **697777** + лид |

**B.6 Шаг 6 — список работ**

  «Назовите **список работ**.»
  8 с → **шаг 7**. Вопрос о цене ТО на шаге 6 → **блок D** → **B.5a** → при
  «продолжаем» снова «Назовите список работ» (или переход к 7, если список уже
  был).

--- C. Шаг 7 — дата, слоты 1С, запись ---

**C.1** «Назовите **желаемую дату и время**». «Как можно скорее» → следующий
рабочий день (`desired_date`); утро/обед/вечер → `day_part`. **Без** рекапа даты
«Всё верно?» **до** запроса в 1С — сразу поиск слотов (**C.2**). Вопрос о цене →
**D** → **B.5a**. Дважды не распознали дату → **697777**.

**C.2** `GET /service/slots`, duration_min **150**. Есть слот → «На … есть
свободное время. **Вас записать?**»; пусто → **697777**; ошибка сети → **697777**.

**C.3** «Да» / «подтверждаю запись» → `GET /service/appointments` → при успехе:
«Вы записаны на … Есть ли ещё вопросы?» → нет → прощание; да/вопрос → **697777**.
Не согласовали время (2× неясно) → **697777**.

--- D. Блок цены по Excel (Chery / Tenet) ---

  • **Меню 14 (2.5):** только **697777**, блок **не** используется.
  • **Шаги 1–4:** цену **не** считаем (нет полного набора или рано); можно
    `price_requested=true` в service_data.
  • **С шага 5** и далее (5, 6, 7, согласование слота): вопрос о стоимости **ТО**
    → полный блок D, затем **B.5a** (короткий вопрос), **не** 5.4.

**Триггер:** маркеры цены + маркеры ТО (то, техобслуживание, техническое
обслуживание). Не блок D: «сколько стоит колодки/кузов» → **5.4** на шаге 5.

**Источник:** `\\server2\…\! ТО Сводная таблица.xlsx` → на server7
`/mnt/sto_to_table/_СТО/! ТО Сводная таблица.xlsx`, код
`dialog/sto_to_summary_table.py` (+ доработка колонки «двигатель коробка»).

**Алгоритм:**

  1. «Я могу назвать **стоимость ТО** для автомобилей **Чери и Тенет** по
     регламенту. Сейчас уточню данные по вашему автомобилю.»
  2. Нужны **марка, модель, пробег** (из шагов 3–4). Нет — краткий добор.
  3. Не Chery/Tenet → «автоматический расчёт недоступен…» → **B.5a** (без
     обязательного перевода).
  4. Несколько строк в Excel → **закрытые вопросы** (повтор при молчании 1×):
     КПП (механика/автомат) → объём (1,6 / 2 л) → привод (передний/полный) —
     только если различаются в таблице.
  5. «Ориентировочная стоимость **{ТО-N}** — **{сумма}** рублей. Предварительный
     расчёт по регламенту.»
  6. → **B.5a** («Продолжаем запись или перевожу…?»).

**Лид:** price_rub, to_label, ответы уточнений, price_announced=true.

--- STT: как принимать ответы клиента ---

Короткие «да» / «нет» часто теряются или искажаются. В сценарии везде:
  • просим **развёрнутый** ответ («верно», «неверно», «это я», «это не я»,
    «подтверждаю запись», «продолжаем», «переведите на ассистента»);
  • после важного поля — **рекап** и один вопрос на подтверждение;
  • пустая реплика / мусор STT → **повтор того же вопроса** (не считать «да»);
  • после **двух** неудачных попыток на одном шаге — предложить перевод на
    ассистента **или** продолжить без поля (см. шаг), **без** автоматического
    перевода, если иное не указано в шаге.

Синонимы «да» (affirmative): верно, правильно, всё верно, согласен, подтверждаю,
это я, да верно, угу, ага, продолжаем, продолжайте, давайте, записывайте.

Синонимы «нет» (negative): неверно, не верно, неправильно, это не я, не согласен,
другое, другая, исправьте, нет.

Синонимы «перевод на ассистента»: ассистент, ассистента сервиса, человек,
оператор, специалист, переведите, соедините с сервисом, мастер сервиса.

**4.2.1. Вопрос о стоимости (нет данных в таблице):**

Бот:
  «Для вашей марки или модели стоимость может назвать ассистент сервиса. Могу
   прервать запись и перевести Вас на ассистента сервиса. Продолжить запись
   или прервать и перевести на ассистента сервиса?»

  • Продолжить / продолжаем / продолжить запись / закончить запись /
    записывайте → **шаг 6** (`price_unknown = true`, в финале сумму не называем).
  • Прервать / перевести / ассистент / специалист → **шаг 5.4** (перевод только
    по явному выбору).

--- Шаг 5. Стоимость ТО (только по запросу клиента) ---

**Принцип (обязательно для всего сценария):**
  • При **плановой пошаговой** записи бот **не называет** стоимость на переходах
    4 → 6 → 7 → 8, даже если сумма уже посчитана в Excel (`price_announced =
    false` по умолчанию).
  • Сумму озвучиваем **только** при явном вопросе клиента (маркеры: «сколько
    стоит», «какая цена», «сколько будет», «сколько заплатить», «стоимость ТО»,
    «сколько обойдётся» и т.п.) — на **любом** шаге сбора данных.
  • Расчёт для слотов, лида и админки может идти **без озвучивания** клиенту.
  • После ответа по **5.0** / **5.1** / **4.2.1** — возврат к тому шагу, где
    прервались (или **шаг 6**, если вопрос задан перед выбором даты).

**5.0. «Сколько стоит ТО?» — в самом начале** (сразу после входа в запись:
  выбрал «запишите» в меню, вариант B, или первые реплики до **шага 1**;
  данных об авто и пробеге ещё **нет**):

Бот:
  «Ориентировочную стоимость смогу назвать, когда уточним автомобиль и пробег.
   Для записи на техническое обслуживание начнём с телефона владельца — проверю
   базу. Стоимость подскажу, когда снова спросите, после того как будут марка,
   модель и пробег. Продолжаем?»

  • «продолжаем» / «да» / «записывайте» / молчание после повтора → **шаг 1**
    (вопрос о цене **не** считается отказом от записи).
  • «только цену» / «не записываться» / «просто узнать цену» →
    Бот: «Назовите, пожалуйста, телефон владеля автомобиля или марку, модель
          и пробег — подскажу ориентир по регламенту, если данные есть в расчёте.»
    → минимальный сбор для расчёта (**шаг 1** или **2.2**); при достаточных
    данных → **5.1** или **4.2.1**; без записи на слот — **ENDED** после ответа,
    если клиент не хочет запись.
  • «ассистент» → **5.4**.

  *(Если клиент **повторно** давит «сколько стоит» до шага 3 — коротко:)*
  «Сначала нужен телефон владельца и пробег — без этого стоимость не посчитать.
   Назовите, пожалуйста, номер телефона владеля автомобиля.» → **шаг 1**.

**5.1. Есть цена в таблице** (Chery/Tenet, модель и пробег уже известны;
  клиент **спросил** о стоимости):

Бот:
  «Ориентировочная стоимость {ТО-N} с работами и запчастями — {сумма} рублей.
   Это предварительный расчёт по регламенту. Скажите: «верно» или «неверно»,
   если хотите уточнить у ассистента.»

  • «верно» / «продолжаем» → `price_announced = true` → продолжение сценария
    (**шаг 6** или шаг, на котором прервались).
  • «неверно» / «ассистент» / «уточнить» → **5.3**.

  Если клиент **не** спрашивал цену — **5.1 не озвучиваем**; после шага 4 →
  **шаг 6**; в финале — **8.2** (без суммы).

**5.2. Нет цены в таблице, клиент спросил** (тот же смысл, что **4.2.1**):

Текст и ветвление — см. **4.2.1**. Вызывается с **шага 5**, если вопрос о цене
задан **не** на ветке 4.2.

**5.3. Клиент усомнился в названной цене (ветка 5.1):**

Бот:
  «Стоимость может уточнить ассистент сервиса. Могу прервать запись и перевести
   Вас на ассистента сервиса. Продолжить запись или прервать и перевести на
   ассистента сервиса?»

    подтвердил (`price_announced = false`).
  • Прервать / ассистент → **шаг 5.4**.

**5.4. Перевод на ассистента** (только после явного выбора клиента):

Бот:
  «Перевожу Вас на ассистента сервиса.»

→ 697777, `ConversationState.ENDED`.

--- Шаг 6. Желаемая дата и время ---

Рекап:

  • «верно» → шаг 7.
  • «неверно» → повтор шага 6 (до 2 попыток), затем шаг 7 с ближайшей датой

  • Клиент спрашивает **стоимость** → **шаг 5** (**5.1** или **4.2.1** / **5.2**),

  • «неверно» / другое время → уточнение (1 раз):

--- Что уже согласовано и работает (свободные слоты) ---
Вход: HTTP **Basic**, в тесте — пользователь «Администратор», пароль пустой.
1. Запрос GET …/service/slots с параметрами date_from, date_to, duration_min
   (если duration_min не указать — по умолчанию 60 минут), опционально post_id.
   Мы **не передаём** post_id в запрос: на выдачу свободных окон это не влияет.
2. Если даты не указать: по твоим сообщениям в переписке (2026-05-08) —
   при отсутствии date_from — завтрашнее утро, при отсутствии date_to —
   +3 суток от date_from; полностью пустой запрос — слоты на три ближайших
   дня по 60 минут.
3. Если свободного времени нет: HTTP 200, в теле {"slots":[]}.
4. В каждом элементе slots[] нужны поля date, time_start, post_id; плюс
   **post_name** (ФИО слесаря строкой), чтобы не делать отдельный справочник
   постов. Префикс post_id в базе у тебя с **русскими** буквами — эталон; мы
   этот код при записи отправляем обратно **без перекодирования** в латиницу.
5. Время в JSON — **самарское** (как в салоне). Внешнего публичного URL к 1С
   нет, доступ из локальной сети.
6. Тело JSON и кириллица в ФИО — в **UTF‑8**, согласовано с заголовком
   Content-Type: application/json; charset=utf-8.

--- Чего не хватает ---
1. **Отмена записи из бота.** GET /service/appointments для **создания** готов
   (2026-05-29, см. журнал). Нужен эндпоинт **отмены** (POST …/cancel или иной)
   и пример ответа при ошибке создания (success=false, текст — чтобы бот перевёл
   на ассистента).
2. **Поиск клиента** по телефону и ФИО: GET …/client/search (или как у тебя
   принято). Если клиент найден — один **фиксированный** формат ответа (человек,
   машины: хотя бы марка, модель, год) и **короткий пример JSON** «нашли», чтобы
   мы один раз настроили разбор.
3. **duration_min=120.** Когда мы запрашиваем слоты на **120 минут**, в ответе
   это всегда окна **ровно на 120 минут**, или любое свободное место, куда
   работа на **120 минут** помещается?
4. **Нормы по работам.** Excel с трудоёмкостями и ценами по позициям (работам)
