ЗАДАЧИ ДЛЯ ПРОГРАММИСТА 1С (ИНТЕГРАЦИЯ С ПРОЕКТОМ ВИКИНГИ)
Конфигурация: 1С Альфа 6.0
================================================================================

--- ОБЩИЕ УСЛОВИЯ ---
• Стыковка: REST API 1С (HTTP-сервисы). Исходим из того, что готовых методов под запись на ТО и лиды в 1С пока нет — их нужно спроектировать и реализовать.
• Инициатор запросов: наш сервер (голосовой бот, телеграм-бот, бэкенд аналитики). 1С запросы к нам пока не инициирует.
• Тестовая база: да.
• Авторизация: рекомендуется схема «логин + пароль приложения» или «токен (API Key) в заголовке» для доступа к HTTP-сервисам 1С; HTTPS при обращении извне. Конкретный механизм согласовать с руководителем IT.

================================================================================
ЭТАП 1. ЗАПИСЬ НА ТО (СЛЕСАРНЫЙ ЦЕХ) (ПРИОРИТЕТ 2)
================================================================================

1.1. Получение свободных слотов (для голосового и телеграм-бота).
     • HTTP-сервис 1С: метод получения свободного времени по «карточке записи в слесарный цех» с учётом поста (поста/постов).
     • Вход: дата (или диапазон дат), идентификатор поста (при необходимости), длительность слота (минуты).
     • Выход: список свободных слотов (дата, время начала, время окончания, пост — при необходимости).
     • Логика в 1С: учёт уже занятых слотов в карточке записи; при необходимости — учёт «нужного времени» из Excel-файлов по автомобилю и видам работ (см. п. 2.4).

1.2. Создание записи на ТО (занятие слота).
     • HTTP-сервис 1С: метод создания записи в карточке записи в слесарный цех.
     • Входные поля:
       — ФИО
       — Телефон (основной и дополнительный — 2 ячейки)
       — E-mail
       — Марка и модель автомобиля
       — Год выпуска
       — Пробег
       — Двигатель: объём, тип топлива, буквенный код
       — Трансмиссия: тип и код коробки, буквенный код, полный или передний привод
       — Желаемые дата и время (слот)
       — Вид работ
       — Комментарий
     • Действие в 1С: создание записи, занятие слота на посту в карточке записи.

1.3. Ответ 1С при создании записи (для сохранения в PostgreSQL нашей стороной):
     • ID созданной записи в 1С
     • Подтверждённое дата и время
     • Статус: принята / отменена (или аналог)

1.4. Отмена записи (освобождение слота).
     • HTTP-сервис 1С: метод отмены записи по ID (например, ID из п. 2.3).
     • Ответ: успех/ошибка. Наша сторона по этому же ID обновит статус в PostgreSQL.

1.5. Передать мне: описание всех методов (получение слотов, создание записи, отмена), форматы запросов/ответов, примеры — для интеграции голосового и телеграм-бота.

================================================================================
РЕКОМЕНДАЦИИ ПО РЕАЛИЗАЦИИ (ЭТАП 1) — для программиста 1С
================================================================================
Ниже — технические рекомендации, как реализовать HTTP-сервисы в 1С. Можно отступить от них по согласованию с руководителем IT.

--- 1. Публикация HTTP-сервисов 1С ---
• В 1С:Предприятие 8.x HTTP-сервисы доступны после публикации информационной базы в режиме веб-сервера.
• Внешний веб-сервер: установить веб-сервер (Apache или IIS) на сервере с 1С, установить модуль расширения 1С для этого веб-сервера (см. документацию 1С «Публикация информационной базы»). В настройках сайта указать каталог публикации и имя базы. Итоговый URL — по настройкам сайта (например, https://1c.company.local/vikingi/).
• Рекомендуется: HTTPS для доступа извне; белый список IP (наш сервер) или авторизация по токену/ключу в заголовке.

--- 2. Рекомендуемые HTTP-методы и шаблоны URL ---
• Получение свободных слотов: GET. Пример шаблона: /slots или /v1/slots (параметры — в query string или в теле — см. ниже).
• Создание записи на ТО: GET (query). Пример: /service/appointments?desired_date=…&fio=…&phone=…&desired_time=…&duration_min=…&post_id=…
• Отмена записи: POST или DELETE. Пример шаблона: /appointments/cancel или /v1/appointments/{id}/cancel (ID в пути или в теле).
Имена и путь можно изменить под принятые в конфигурации 1С Альфа (например, префикс /alfa/ или /service/).

--- 3. Формат данных ---
• Запросы и ответы: JSON.
• Кодировка: UTF-8. Заголовок запроса: Content-Type: application/json; charset=utf-8.
• Ответы: всегда возвращать JSON; при ошибке — HTTP-код 4xx/5xx и в теле объект с полем "error" или "message" (текст ошибки).

--- 4. Авторизация ---
• Рекомендуется проверять каждый входящий запрос:
  — заголовок X-API-Key: <ключ>. Аналогично — ключ хранится в 1С, при несовпадении возвращать 401 Unauthorized.
• В первом запросе (например, при настройке) согласовать с нашей стороной один общий ключ/токен для ботов и бэкенда.

--- 5. Примеры запросов и ответов (ЭТАП 2) ---

5.1. Получение свободных слотов
  Метод: GET
  URL (пример): https://<сервер_1С>/<публикация>/hs/service/slots?date_from=2026-02-21&date_to=2026-02-22&duration_min=60&post_id=1
  Параметры (query): date_from (YYYY-MM-DD), date_to (YYYY-MM-DD), duration_min (число, минуты), post_id (опционально).
  **date_to (2026-06-18, А. Шилкин):** начало дня после последнего включённого (exclusive).
    — слоты за 1 день 21.02: date_from=2026-02-21&date_to=2026-02-22
    — за 2 дня 21–22: date_from=2026-02-21&date_to=2026-02-23
    Не передавать date_from=date_to для одного дня — интервал обрежется пустым.
  Ответ 200 (JSON):
  {
    "slots": [
      { "date": "2026-02-20", "time_start": "09:00", "time_end": "10:00", "post_id": "1" },
      { "date": "2026-02-20", "time_start": "10:00", "time_end": "11:00", "post_id": "1" }
    ]
  }

5.2. Создание записи на ТО
  Метод: GET
  URL (пример): http://<сервер_1С>/<публикация>/hs/service/appointments
  Query-параметры (актуализация 2026-05-29, А. Шилкин; доп. 2026-06-18):
    desired_date  — YYYY-MM-DD
    fio           — ФИО клиента (UTF-8)
    phone         — телефон; два номера через **запятую** (контактный, номер звонка),
                    строка до **50 символов** (напр. 79023730101,79023730808)
    desired_time  — HH:MM
    duration_min  — длительность слота в минутах (из расчёта бота / 1С slots)
    post_id       — код поста из выбранного элемента slots[] (кириллица, без перекодирования)
    mileage, brand, model, listofworks — опционально (поддерживаются с 2026-06-18)
  Пример:
    GET .../service/appointments?desired_date=2026-05-29&fio=Тестовый%20клиент&phone=+8(912)125-6633&desired_time=13:00&duration_min=60&post_id=ЦБ00000199
  Ответ 200 (JSON):
  {
    "success": true,
    "appointment_id": "00000004128",
    "appointment_Date": "2026-05-28T21:57:57"
  }
  При ошибке (слот занят, неверные данные): ожидаем success=false и текст/код ошибки
  (формат уточнить у 1С). Тот же path с date_from/date_to — **список** записей,
  не создание: {"appointments":[…]}.

  *(Ниже — устаревший черновик POST+JSON до согласования 2026-05-29; не использовать.)*
  ~~Метод: POST, тело JSON с fio, phone, car_brand, …~~

5.3. Отмена записи
  Метод: POST (или DELETE)
  URL (пример): https://<сервер_1С>/<публикация>/hs/service/appointments/cancel
  Тело (JSON): { "appointment_id": "uuid-из-п.2.3" }
  Ответ 200: { "success": true }. При ошибке: 404 или 400, { "success": false, "error": "текст" }.

--- 6. Пошаговый план в 1С ---
1. В конфигураторе 1С: создать HTTP-сервис (например, имя ServiceAPI), описать шаблоны URL для слотов, создания и отмены записи.
2. Для каждого шаблона — указать метод (GET/POST) и привязать обработчик (общая обработка или метод модуля).
3. В обработчике: чтение входящего потока (тело запроса), разбор JSON (средства 1С для работы с JSON), проверка авторизации по заголовку, вызов бизнес-логики (запрос к карточке записи, создание документа и т.д.), формирование ответа в JSON и запись в поток ответа.
4. Опубликовать информационную базу на сервере 1С (встроенный веб-сервер или через Apache/IIS по инструкции 1С).
5. Проверить доступность по URL с рабочей станции (curl или Postman), затем передать нашей стороне описание методов, итоговые URL и примеры (как в п. 2.6 ТЗ).
