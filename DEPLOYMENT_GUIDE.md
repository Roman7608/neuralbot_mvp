### 2. PostgreSQL

#### 2.1. Установка PostgreSQL

**На сервере 3 (локальный сервер проекта):**

**Регистрация:** PostgreSQL - это открытое ПО, **никаких регистраций не требуется**. Просто скачивается и устанавливается.

**Linux (Ubuntu/Debian):**
```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql
```

**Windows:**
- Скачать установщик с https://www.postgresql.org/download/windows/
- Установить PostgreSQL
- Запустить службу PostgreSQL

**Проверка установки:**
```bash
sudo -u postgres psql --version
# Должно показать версию, например: psql (PostgreSQL) 14.9
```

#### 2.2. Настройка базы данных

**Создание базы данных:**
```sql
-- Подключение как пользователь postgres
sudo -u postgres psql

-- Создание базы данных
CREATE DATABASE vikingi_analytics;

-- Создание пользователя для 1С
CREATE USER ics_user WITH PASSWORD 'secure_password_here';

-- Создание пользователя для системы аналитики
CREATE USER analytics_user WITH PASSWORD 'secure_password_here';

-- Права доступа
GRANT CONNECT ON DATABASE vikingi_analytics TO ics_user;
GRANT CONNECT ON DATABASE vikingi_analytics TO analytics_user;

-- Вход в базу данных
\c vikingi_analytics

-- Права на создание таблиц для analytics_user
GRANT ALL PRIVILEGES ON DATABASE vikingi_analytics TO analytics_user;

-- Права на чтение для ics_user (только SELECT)
-- (Будет настроено после создания таблиц)
```

#### 2.3. Настройка подключения из 1С

**В 1С Альфа 6.0:**
1. "Администрирование" → "Подключение к внешним источникам данных"
2. Тип: PostgreSQL
3. Параметры подключения:
   - Сервер: IP-адрес сервера 3
   - Порт: 5432 (по умолчанию)
   - База данных: `vikingi_analytics`
   - Пользователь: `ics_user`
   - Пароль: (установленный пароль)
4. Тест подключения

**Важно:**
- Настроить файрвол на сервере 3 для доступа к PostgreSQL с сервера 1
- Использовать SSL-соединение для безопасности (рекомендуется)

#### 2.4. Настройка файрвола

**Linux (ufw):**
```bash
# Разрешить доступ к PostgreSQL только с сервера 1С
sudo ufw allow from <IP_сервера_1С> to any port 5432

# Или для всех (менее безопасно, но проще)
sudo ufw allow 5432/tcp
```

**Windows:**
- Настроить правила файрвола Windows для порта 5432

#### 2.5. SSL-соединение (рекомендуется)

**Генерация сертификатов:**
```bash
# На сервере 3
sudo -u postgres mkdir -p /var/lib/postgresql/ssl
cd /var/lib/postgresql/ssl

# Генерация сертификата
openssl req -new -x509 -days 365 -nodes -text -out server.crt -keyout server.key -subj "/CN=postgresql.vikingi.local"
chmod 600 server.key
chown postgres:postgres server.key server.crt
```

**Настройка PostgreSQL для SSL:**
В файле `/etc/postgresql/14/main/postgresql.conf`:
```
ssl = on
ssl_cert_file = '/var/lib/postgresql/ssl/server.crt'
ssl_key_file = '/var/lib/postgresql/ssl/server.key'
```

**Перезапуск PostgreSQL:**
```bash
sudo systemctl restart postgresql
```

#### 4.3. Хранилище аудио (server7)

На server7 два носителя: SSD (проект) и HDD (аудио). **Все аудиозаписи звонков сохраняются только на HDD.**

**Требования:**
- HDD примонтирован в `/mnt/audio_calls` (метка `audio_calls`, ~458 ГБ)
- Конфиг: `AUDIO_CALLS_ROOT=/mnt/audio_calls/calls` (переопределить через `.env` при необходимости)

**Структура:**
```
/mnt/audio_calls/calls/
├── auto/YYYY-MM-DD/     # автозабор из SpRecord (server5)
└── manual/
    ├── OP/              # ручная загрузка — отдел продаж
    └── STO/             # ручная загрузка — СТО
```

**Docker:** admin-panel монтирует `/mnt/audio_calls` с правами чтения и записи (для загрузки файлов).

**Файлы:** `config.py` (AUDIO_CALLS_ROOT), `call_analytics/autofetch_sprecord.py`, `admin_panel/main.py`.

**Автозабор SPRecord + очистка (ежедневно в 23:55):**
- Пайплайн: автозабор записей за день с SpRecord (server5) → копирование на HDD → удаление записей старше 14 дней.
- Скрипт: `scripts/daily_sprecord_pipeline.sh`
- Cron на server7:
  ```
  55 23 * * * cd /home/vikingi/VikingiAll && bash scripts/daily_sprecord_pipeline.sh
  ```
- Лог: `logs/vikingi_autofetch.log` (или `VIKINGI_AUTOFETCH_LOG` в `.env`).
- Перед настройкой cron: SpRecord должен быть примонтирован на `/mnt/sprecord`.
- **После перезагрузки server7:** см. полные команды `smbclient` / `mount` / `fstab`: [`docs/SPRECORD_MOUNT_SERVER7.md`](docs/SPRECORD_MOUNT_SERVER7.md).

### Чек-лист при подключении к сети

1. **Получить от Солощева / IT-отдела:**
   - Статический IP для сервера (или DHCP-резервирование)
   - IP сервера 1С Альфа 6.0
   - Подсеть LAN компании (например, `192.168.1.0/24`)
   - Доступ в интернет (для Telegram-бота и Инфолады)

2. **Физическое подключение:**
   - Подключить Ethernet к серверу
   - Проверить IP: `ip addr show`
   - Проверить интернет: `ping 8.8.8.8`

3. **Firewall:**
   ```bash
   sudo ICS_SERVER_IP=<IP_1C> INFOLADA_IP=217.113.112.24 LAN_SUBNET=<ПОДСЕТЬ> bash setup_firewall.sh
   ```

4. **Excel-справочники СТО (через админку):**
   - Открыть `http://<IP_СЕРВЕРА>:8000/sto` (роли 5-6)
   - Скачать текущий norma.xlsx, отредактировать, загрузить обратно
   - При загрузке автоматически создаётся бэкап

5. **PostgreSQL для 1С:**
   - Проверить подключение с сервера 1С:
     ```
     psql -h <IP_СЕРВЕРА> -p 5433 -U ics_user -d vikingi_analytics
     ```
   - Передать программисту 1С: IP, порт 5433, user `ics_user`, пароль

6. **SIP (Asterisk → Инфолада):**
   - Заполнить `.env`: `INFOLADA_SIP_USER`, `INFOLADA_SIP_PASSWORD`
   - Попросить Арсения (Инфолада) внести IP сервера в белый список ACL
   - Запуск: `docker compose up -d asterisk voice-bot`
   - Проверить регистрацию:
     ```bash
     docker exec asterisk asterisk -rx "pjsip show registrations"
     ```

7. **1С HTTP-сервисы:**
   - Заполнить `.env`: `ICS_ALFA_HTTP_URL`, `ICS_ALFA_API_KEY`
   - Передать программисту 1С файлы ТЗ: `Tasks_1C_integration_1.txt`, `ICS_ALFA_INTEGRATION_SPEC.md`
   - После публикации HTTP-сервисов 1С — проверить:
     ```bash
     curl -H "X-API-Key: <KEY>" "http://<IP_1C>:8080/vikingi/hs/client/search?phone=79001234567"
     ```

8. **Admin-panel:**
   - Открыть в браузере: `http://<IP_СЕРВЕРА>:8000`
   - Создать пользователей для руководителей (роли 4-6)
   - Проверить экспорт лидов: кнопка CSV / Excel на странице "Лиды"

9. **Telegram-бот:**
   - Проверить: `docker compose logs telegram-bot`
   - Отправить тестовое сообщение боту `@Neuro_auto_bot`

## GPU и расписание LLM аналитики

**Голосовой бот работает круглосуточно.** STT-сервис (GigaAM) загружает модель при старте и **держится в VRAM постоянно**, даже без звонков.

| Время | GPU | LLM аналитики (нормализация, оценка, классификация) |
|-------|-----|-----------------------------------------------------|
| **День** | При нескольких одновременных звонках GPU занята STT | **Не запускать** — нет места |
| **После 23:50** | Звонков мало, нагрузка на STT низкая, GPU частично свободна | **Запускать** — n_ctx=1024 для экономии VRAM |

**Правила:**
- LLM в аналитике — **только после 23:50** (когда вероятность звонков низкая)
- LLM **никогда не запускать на CPU** — только GPU
- При совместной работе с STT: `NORMALIZE_LLM_N_CTX=1024` (по умолчанию)

### Установка llama-cpp-python с CUDA

Стандартный `pip install llama-cpp-python` ставит **CPU-сборку**. Для LLM аналитики (нормализация, оценка, классификация) нужна **CUDA-сборка**, иначе обработка будет очень медленной (минуты на текст).

**Для GPU (обязательно на сервере с NVIDIA + CUDA):**

```bash
source venv/bin/activate
pip uninstall llama-cpp-python -y
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu121 --force-reinstall
```

- `cu121` — для CUDA 12.1 (проверить: `nvidia-smi` → CUDA Version)
- Для CUDA 11.8 замените на `cu118`

**Если в requirements.txt есть `llama-cpp-python`** — он даёт только базовую (CPU) установку. После `pip install -r requirements.txt` выполните команду выше для GPU-версии.

**Проверка CUDA:**
```bash
ldd venv/lib/python3.*/site-packages/llama_cpp/*.so 2>/dev/null | grep -i libcuda
```
Если в выводе есть `libcuda` — сборка с поддержкой GPU.
